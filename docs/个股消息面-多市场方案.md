# 个股消息面 · 多市场支持方案（美 / 日 / 韩 / 港股）

> 现状：`个股消息面` 原只支持 A 股（东财公告库 `np-anotice-stock.eastmoney.com`）。
> 本文给出一套**实测过**的扩展方案，包含每个市场的源、字段映射、标签词表、降级策略与工作量。
>
> **实施状态（2026-11-03）**：✅ 港股、✅ 美股、✅ 日股、✅ 韩股 全部上线。
> 落地时的发现见文末「实施记录」与「日韩实施记录」——**日股最终没有用 TDnet，换成了 Yahoo!ファイナンス**。

---

## 一、结论先行

| 市场 | 推荐源 | 实测 | 数据性质 | 落地难度 |
|---|---|---|---|---|
| **港股** | 东财公告库 `ann_type=H` | ✅ 200 / JSON | **公告**（繁体） | ⭐ 极低（同一个接口，改参数） |
| **美股** | SEC EDGAR `data.sec.gov` | ✅ 200 / JSON 160KB | **监管申报**（8-K/10-Q/Form 4…） | ⭐⭐ 低（要 CIK 映射） |
| **日股** | TDnet 適時開示 | ✅ 200 / HTML 67KB | **公告**（日文） | ⭐⭐⭐ 中（HTML 解析） |
| **韩股** | Naver `m.stock.naver.com` | ✅ 200 / JSON | **新闻**（韩文，非公告） | ⭐⭐⭐ 中（无官方公告源） |

一句话：**港股几乎白送，美股最权威，日股要写解析器，韩股只能拿新闻**。

## 二、实测明细（2026-11-03）

### 2.1 港股 —— 东财公告库（推荐）

```http
GET https://np-anotice-stock.eastmoney.com/api/security/ann
    ?sr=-1&page_size=40&page_index=1&ann_type=H&client_source=web&stock_list=00700
Referer: https://data.eastmoney.com/
```

实测返回 `200 / 3,413 bytes`：

```json
{"data":{"list":[{
  "art_code":"AN202610221830790708",
  "codes":[{"ann_type":"H","short_name":"腾讯控股","stock_code":"00700"}],
  "columns":[{"column_code":"011010011001","column_name":"債務證券發行通函或定價補充文件"}],
  "notice_date":"2026-10-22 00:00:00",
  "title":"..."
}]}}
```

- **和 A 股接口完全同构**，只是 `ann_type=A → H`、`stock_list=600519 → 00700`；
- `column_name` 是**繁体中文**，标签词表需要繁简双写；
- 代理已在白名单（`np-anotice-stock.eastmoney.com`），**零新增配置**。

**工作量：约 0.5 小时**（把 `toAnnCode` 放开港股 + 标签词表加繁体）。

### 2.2 美股 —— SEC EDGAR（推荐）

**① ticker → CIK 映射**（缓存 24 小时，797KB）

```http
GET https://www.sec.gov/files/company_tickers.json
User-Agent: MathQuantLab/0.1 (research; your@email.com)
```

返回 `{"0":{"cik_str":320193,"ticker":"AAPL","title":"Apple Inc."}, ...}`，全量约 1 万家公司。

**② 取最近申报**（缓存 30 分钟，160KB）

```http
GET https://data.sec.gov/submissions/CIK0000320193.json
User-Agent: MathQuantLab/0.1 (research; your@email.com)
```

实测 `200 / 163,755 bytes`，关键结构：

```json
{"cik":"0000320193","name":"Apple Inc.","tickers":["AAPL"],
 "filings":{"recent":{
   "accessionNumber":["0000320193-26-000024", ...],   // 1001 条
   "filingDate":["2026-11-02", ...],
   "form":["8-K","4","4","10-Q", ...],
   "items":["2.02,9.01", "", ...],                    // 8-K 的事项编号
   "primaryDocDescription":["8-K", ...],
   "primaryDocument":["aapl-20261102.htm", ...]
 }}}
```

申报详情页：`https://www.sec.gov/Archives/edgar/data/{cik}/{accession去横线}/{primaryDocument}`

**form → 标签映射**

| SEC form | 含义 | 标签 | 方向 |
|---|---|---|---|
| `8-K` + items 含 `2.02` | 业绩发布 | 业绩 | 看内容 |
| `8-K` + items 含 `5.02` | 高管变动 | 人事变动 | 中性 |
| `8-K` + items 含 `1.01` | 重大协议 | 中标合同 | 偏多 |
| `8-K` + items 含 `2.01` | 完成收购 | 重组并购 | 偏多 |
| `8-K`（其他 items） | 重大事件 | 重大事件 | 中性 |
| `10-Q` / `10-K` / `20-F` | 财报 | 业绩 | 看内容 |
| `4` | 内部人交易 | 内部人交易 | ⚠️ 未知（见下） |
| `SC 13D` | 举牌（主动） | 大额持股 | 偏多 |
| `SC 13G` | 大额持股（被动） | 大额持股 | 中性 |
| `S-1` / `424B` / `F-1` | 增发注册 | 定增融资 | 偏空 |
| `DEF 14A` | 股东大会 | 说明会调研 | 中性 |
| `144` | 老股出售通知 | 减持 | 偏空 |
| `25-NSE` | 退市通知 | 立案处罚 | 偏空 |

⚠️ **Form 4 的方向拿不到**：submissions JSON 只给「有内部人交易」，买还是卖要看 Form 4 的 XML（`xslF345X06/form4.xml`，需再请求一次 + 解析 `transactionCode`：P=买入、S=卖出、A=授予、M=行权）。方案：
- 一期：标「内部人交易」，方向记中性，不参与多空比；
- 二期（可选）：只对最近 5 条 Form 4 拉 XML 判方向，缓存。

**工作量：约 1 天**（CIK 映射 + form 映射 + 限流 + 缓存 + 测试）。

**限流**：SEC 要求 ≤10 请求/秒且必须带可联系 UA。代理层固定 UA，前端加 10 分钟缓存 + 串行队列。

### 2.3 日股 —— TDnet 適時開示（唯一官方免费源）

```http
GET https://www.release.tdnet.info/inbs/I_list_001_20261030.html
User-Agent: Mozilla/5.0 ...
```

实测：**工作日 `200 / 66,988 bytes`**；休市日（11-03 文化日）返回 1,779 bytes 的「に開示された情報はありません」。

表格结构（可直接用 DOMParser 解析）：

```html
<tr>
  <td class="oddnew-L kjTime">20:00</td>
  <td class="oddnew-M kjCode">96580</td>
  <td class="oddnew-M kjName">ビジ太田昭和</td>
  <td class="oddnew-M kjTitle"><a href="140120261030561903.pdf">持分法適用会社に対する公開買付に係る契約締結に関するお知らせ</a></td>
  <td class="oddnew-M kjPlace">東</td>
</tr>
```

- `kjCode` 是 **5 位**（`7203` → `72030`，末位 0）；
- `kjTitle` 的 `href` 是相对 PDF 路径，拼 `https://www.release.tdnet.info/inbs/`；
- **只有当日全量列表**，没有按个股查询的公开接口 → 前端过滤：拉最近 5 个交易日的列表（约 330KB），筛 `kjCode`。

## 三、代码改造

### 3.1 数据模型

```ts
// src/math/stockNews.ts
export type AnnMarket = 'CN' | 'HK' | 'US' | 'JP' | 'KR';

export interface AnnInput {
  id: string;
  title: string;
  date: string;
  column?: string;
  url?: string;
  market?: AnnMarket;   // 新增：决定用哪套标签词表
  kind?: string;        // 新增：SEC form / TDnet 分类，展示用
}

// 标签分类按市场分派
export function classifyAnn(title: string, column?: string, market: AnnMarket = 'CN')
```

标签体系**复用现有 18 类**（回购/减持/增持/中标/获批/业绩/分红/解禁/立案…），不新增概念——四个市场的事件语义高度重合，只有「内部人交易」「大额持股」需要新增 2 类。

### 3.2 适配器拆分

```
src/data/stockNews/

  cn.ts        // 东财 ann_type=A（现有逻辑迁入）
```

`index.ts` 按 `picked.market` 分派，统一返回 `FetchAnnResult { list, total, name? }`，页面层不用改。

## 七、实施记录（2026-11-03）

港股 + 美股已按本方案落地，过程中有三个方案里没预料到的点：

1. **港股「翌日披露报表」会淹没面板**
   腾讯天天回购，40 条公告里 34 条是「翌日披露报表」。按方案直接打标，会得出「回购 32 次」这种失真结论。
   → 新增 `routine`（例行披露）判定：不计入多空与公司行为统计、排序沉底、UI 灰化；但单独统计「其中 N 条为股份购回」，避免丢掉「持续回购」这个关键信息。

2. **SEC 的 User-Agent 不是「随便写一个」就行**
   `MathQuantLab/0.1 (local research tool; contact: local@localhost)` 被 403 拒绝，报
   `Your Request Originates from an Undeclared Automated Tool`。
   把联系方式换成合法邮箱格式（`mathquant@example.com`）后立即 200。
   → 代理层 UA 必须形如 `AppName/version contact@domain`。

3. **Form 144 不能当「已减持」**
   Form 144 只是「拟出售证券」通知，未必成交。一期把它记为 `减持` 标签但 **tone=0**，
   并在结论里单独写「另有 N 笔拟出售申报，属于计划性减持，未必全部执行」。

另外两个小修：
- 美股 form 代号（`8-K`/`144`/`10-Q`）对普通用户不可读 → 加中文说明（「8-K 重大事项」「144 拟出售证券」）；
- 消息面面板原本嵌在「行情加载成功」分支里，美股行情失败时整块消失 → 与行情解耦，行情不可用时仍可看公告。

**最终结构**：

```
src/data/stockNews/
  index.ts   路由 + 10 分钟缓存 + 代码→市场判定
  em.ts      东财（A 股 ann_type=A / 港股 ann_type=H）
  sec.ts     SEC EDGAR（CIK 表 24h 缓存 + submissions 30min 缓存）
src/math/stockNews.ts
  18 → 21 类标签（新增 内部人交易 / 大额持股 / 重大事件）
  繁简归一（港股）+ form 枚举映射（美股）
  例行披露剔除 + 公司行为画像
```

测试：`tests/stockNews.test.ts` 50 例（A 股 26 + 港股繁简 8 + 美股 form 10 + 市场路由 3 + 例行披露 3）。

## 八、日韩实施记录（2026-11-03）

### 8.1 日股：TDnet 方案被否决，改用 Yahoo!ファイナンス

原方案打算「拉 TDnet 当日全量列表，前端按代码过滤」。实测发现这条路走不通：

- `I_list_001_YYYYMMDD.html` **一页只给 100 条**（约最近两小时），一天的披露有 500+ 条，要翻页；
- 丰田这种公司一天可能只有 1 条披露，排在很后面，翻到第 5 页才出现；
- 没有按证券代码查询的公开接口（`I_search_001_7203.html` 直接 404）。

改用 **Yahoo!ファイナンス 的个股適時開示页**：

```http
GET https://finance.yahoo.co.jp/quote/7203.T/disclosure
```

- 按代码直查，覆盖数月，带 PDF 链接（Yahoo 转存的 `finance-frontend-pc-dist.../disclosure/YYYYMMDD/xxx.pdf`）；
- 页面是 Next.js 渲染，class 名 hash 化，只能用结构选择器：`a[href*="/disclosure/"] > h3`；
- 日期从 PDF 路径 `/disclosure/(\d{8})/` 提取；
- 同时提供**日文原文 + TDnet 英文版**标题，所以日文词表之外还补了英文关键词（`Repurchase of Shares`、`Financial Results`、`Tender Offer`…）。

实测丰田：30 条披露 → 业绩 4、回购 3、其他 23，`自己株式の取得状況に関するお知らせ` 正确判为回购。

### 8.2 韩股：接口结构是个坑

`m.stock.naver.com/api/news/stock/005930` 返回 `total: 1` 的「相关新闻」，而且内容经常是房地产、宏观经济这类泛财经稿。

换成 `api.stock.naver.com/news/stock/005930`，返回 17KB、20 条真实个股新闻。**但结构是「每条新闻一个 bucket」的数组**：

```json
[{"total":1,"items":[{...}]}, {"total":1,"items":[{...}]}, ...]
```

只取 `json[0]` 会只剩 1 条——必须 `flatMap` 展平。

### 8.3 五个市场的最终形态

| 市场 | 源 | 数据性质 | 标签依据 | 方向可信度 |
