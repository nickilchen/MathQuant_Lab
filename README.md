![市场体检总览 · 暗夜矩阵主题](./docs/screens/overview-dark.jpg) ![市场体检总览 · 量子白主题](./docs/screens/overview-light.jpg) ![个股分析 · 趋势信号与操作策略](./docs/screens/stock-analysis.jpg)

纯前端（Vite + React + TypeScript + ECharts）的股市数学模型应用：把六类经典市场模型做成**可交互、可回测、可解释**的页面，并内置**策略引擎**自动合成买卖信号，所有计算在浏览器端完成，零后端。

- **看得懂**：每个模型页底部都有「📐 数学原理」折叠面板，公式与推导直接摊开
- **算得快**：`math/` 全部是纯函数，31 个测试文件 / 461 个用例覆盖边界与口径
- **拿得到**：五市场行情与消息面走多源降级 + 按 host 限流，任一数据源故障不白屏
- **不造假**：指数类页面取不到真实数据就显式降级并标注 DEMO；个股分析全程禁用模拟数据，取不到即显示「实时行情暂不可达」并支持重试
- **手机可用**：≤768px 自动切换汉堡抽屉导航与单行工具条，表格 / 热门标的在自身容器内横滚，不撑破页面；桌面端布局不变

## 数据源与降级策略

每个标的按「主源 → 备用源 → 本地缓存 → 模拟数据」顺序降级，任何单一数据源故障都不会让页面失效：

| 源 | 覆盖 | 端点 | 验证 |
|---|---|---|---|
| 腾讯 | A股/港股（指数·ETF·个股） | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | ✅ 直连 + 代理 |
| 东方财富 | 全球指数（100.*：美/日/港/台等） | `push2his.eastmoney.com/api/qt/stock/kline/get` | ✅（网络受限时会熔断） |
| **东财数据中心** | **A股机构持仓 / 股东户数** | `datacenter-web.eastmoney.com`、`emweb.securities.eastmoney.com` | ✅ 直连（F10 需代理） |
| **新浪** | **A/ETF + 美股指数 + 美股 ETF/个股** | `quotes.sina.cn/.../CN_MarketDataService.getKLineData`、`stock.finance.sina.com.cn/.../US_MinKService.getDailyK` | ✅ 标普500 数据与东财逐分一致 |
| Naver | 韩国（指数 + 个股） | `api.finance.naver.com/siseJson.naver` | ✅ |
| Yahoo | 全球指数兜底（日经/港股等） | `query1.finance.yahoo.com/v8/finance/chart/` | 视网络可达 |

**熔断机制**：某源连续失败 2 次即冷却 5 分钟，期间直接跳过切到备用源——某域名被系统性阻断时，切换耗时从 5.6 秒降到 0.2 秒。

其余保障：

| 环节 | 说明 |
|---|---|
| 本地代理 | `npm run dev` 走 Vite 代理；`npm run serve` 走 `server.mjs` 的 `/px/{host}/{path}` 通用代理（host 白名单，非白名单 403）。新浪/Yahoo 无 CORS 头，浏览器环境统一经此代理 |
| 代理环境 | `server.mjs` 自动读取 `HTTP_PROXY/HTTPS_PROXY`（企业内网/网关场景），无代理时为空操作 |
| 本地缓存 | localStorage，7 天有效；徽标显示**缓存年龄**（如「缓存·3小时前」） |
| **后台自愈** | 走缓存/模拟数据时立即返回，同时后台 15s/60s/180s 尝试实时源，成功后静默更新并自动翻转徽标 |
| 模拟数据 | 内置 GBM（带隐性状态切换），页面显著标注 DEMO，绝不伪装成真实行情 |

所有源请求均带 `cache: 'no-store'`——金融终端不使用浏览器 HTTP 缓存。

> ⚠️ Pages 是**纯静态托管**，不提供本地运行时的 `/px/{host}` 服务端代理。2026-11-14 线上实测的可用范围：

>
> **完整五市场体验请按上面的命令本地运行**：`npm run serve` 会启动带代理的本地服务。

## 降级链与「不造假」原则

`主源 → 备用源（五源按标的自动分流）→ 本地缓存（7 天）→ 显式 DEMO`，任一环节失败自动降级、页面不白屏，顶栏实时显示当前数据源与缓存年龄；源覆盖、熔断与后台自愈详见上文「数据源与降级策略」。

**个股分析是唯一例外**：`allowDemo=false` 全程禁用模拟数据。实时源与缓存都取不到时，页面显示「实时行情暂不可达」、列出已尝试的源并给出重试按钮，绝不用 GBM 冒充真实行情。

## 模型地图

| 页面 | 模型 | 核心算法 | 关键公式 |
|---|---|---|---|
| 总览 | 四模型信号聚合 | — | 观点归一化等权平均 |
| **情绪晴雨表** | **七维情绪合成 + 五档天气** | **tanh 压缩打分 + 标题词典多空 → 加权归一 → 分档** | **T = Σwᵢsᵢ/Σwᵢ，w=(0.20,0.16,0.20,0.10,0.12,0.10,0.12)** |
| **机构持仓** | **机构类型占比 + 属性穿透** | **股东名称规则分类 + HHI 集中度 + 可解释评分** | **r_i = 持股/总股本；HHI = Σwᵢ²；Score = 50 + Σδ** |
| **实时监控** | **消息面 + 个股异动定时盯盘（A/港/美/日/韩）** | **行情腾讯主 + 东财/新浪/Naver/Yahoo JP 备；快讯财联社主 + 新浪 7×24/东财快讯备；分频轮询 30s/60s/5min + 全局引擎 + 顶栏未读** | **告警 = 快讯档位 ≥ A ∨ \|涨跌幅\| 阈值穿越 ∨ 瞬时跳变 ≥ 阈值 ∨ 新公告；按 host 最小间隔/每分钟预算/失败指数退避防限流，休市 ×3、后台 ×4 降频** |
| **波段 · 抄底** | **趋势回调/突破 + 恐慌超跌反弹（A/港/美/日/韩）** | **MA20/MA60/ADX/ATR/RSI + 20 日结构位；恐慌评分 + 该股历史同类样本胜率** | **入场 = MA20 或突破位；止损 = 结构位 − 1.5 ATR；目标 = 入场 + 2R；仓位 = 风险预算 ÷ 每股风险** |
| **降波筑底** | **大涨 → 逐级下跌 → 波动/量能双收敛 → 低点抬高 → 放量突破（A/港/美/日/韩）** | **ATR%、布林带宽、已实现波动三项压缩比 + 20 日均量 + 唐奇安下轨 + 40 日回归斜率 + 均线粘合 + ADX + OBV 底背离，六维 100 分** | **波动压缩比 = 当前 ÷ 下跌段峰值；试探仓 = 本金 × 10%；止损 = 底部低点 − 0.5 ATR（破底即走）；确认档需放量 ≥1.5× 站上 20 日颈线，目标 = 颈线 / 箱体量度 / 0.618 反弹位** |
| **价值估值评断** | **季度财报驱动的相对估值（A/港/美/日/韩）** | **TTM EPS + 该股自身历史 PE/PB 分位（25/50/75）→ 悲观/合理/乐观三档具体股价** | **合理价 = TTM EPS × PE 中位数；差额 = 合理价 − 现价；A 股 TTM 用累计差分，海外用最近 4 季相加** |
| **做 T 分析** | **日内回转决策（正 T / 倒 T / 观望 / 不适合）** | **腾讯分时 VWAP + 近 20 日振幅 + 真实交易成本盈亏平衡；两腿价格区间与数量** | **成本 = 2·max(额·佣金, 5 元) + 额·印花税 + 2·额·过户费；剩余空间 = 均振幅 − 已走振幅** |
| **个股分析** | **趋势法 + 技术面体检 + 基本面 + 消息面标签** | **均线/ADX/唐奇安/线性回归/量价；MACD/RSI/KDJ/BOLL/ATR/OBV；东财估值与财务快照；公告关键词 + SEC form + 港股繁简 + 日韩词表** | **趋势 score = 50 + 50·Σwᵢsᵢ；技术面 = 50 + Σ指标加减分；importance = 标签权重 + 时效 + 金额** |
| **策略信号** | **策略引擎** | **观点加权合成 + 风控叠加** | **0.3·HMM+0.3·因子+0.2·波动率+0.2·MLP；逆势降档/波动率收缩/技术封顶/风险档位** |

波段识别趋势回调 / 箱体突破 / 突破延伸，给入场、止损、目标与仓位；抄底先给恐慌程度打分，再回答「同样跌幅后 1/3/5 天的涨跌概率」。覆盖五个市场并按交易制度调整。

**第三个 tab「降波筑底」**识别的是以月计的中期底部构造：主升前置（60 日涨幅 ≥30%、距顶 20~180 日）→ 自高点回撤 ≥20% → 波动与量能同时收敛到下跌段峰值的 60% 以下 → 低点不再下移、均线粘合走平、ADX 力竭 → 放量站上 20 日颈线。六维打分 100 分，输出五档信号：下跌未完 / 降波中·观察 / 筑底中·小仓试探 / 筑底确认·买入 / 筑底失败·离场。

核心规则是 **波动收敛 ≠ 见底**：下跌中继平台同样会缩量横盘，所以只收敛不突破一律停在观察档，只给试探仓；试探仓默认 10%，止损为底部低点 − 0.5 ATR，**破底即走**，加仓的唯一条件是放量站上颈线后才升至 30%。全部指标因果（峰值基准不含最新窗口、突破量比用昨日均量），至少需 120 根日 K，建议 250 根以上。

### 情绪晴雨表（七维 → 五档天气）

![情绪晴雨表：七维打分与消息面分级](./docs/screens/modules/07-sentiment.jpg)

`/sentiment` 把「全网情绪、资金、涨跌、讨论」拆成七个可解释的维度，各自打 0~100 分，再加权成一个市场温度，
映射成 ☀️晴 / ⛅多云 / ☁️阴 / 🌧️小雨 / ⛈️暴雨 五档。

| 维度 | 权重 | 回答什么问题 | 口径 |
|---|---|---|---|
| 涨跌广度 | 20% | 多少股票在涨 | 全 A 涨跌家数 + 涨跌幅中位数 |
| 打板强度 | 16% | 短线资金敢不敢打 | 涨停/跌停比 40% + 封板率 30% + 连板高度 30% |
| 资金流向 | 20% | 真金白银往哪走 | 主力净流入占成交额 72% + 融资净买入占余额 28% |
| 量能热度 | 10% | 参与热度 | 成交量 / 20 日均量（按交易时段折算） |
| 结构扩散 | 12% | 普涨还是独苗 | 上涨行业占比 + 行业涨幅中位 |
| 波动恐慌 | 10% | 恐慌程度（反向） | 20 日波动率 / 60 日基准 |
| **全网讨论** | **12%** | **散户在聊什么** | **股吧人气榜赚钱效应 60% + 热帖多空比 40%** |

**打分用 tanh 而不是线性**：上涨占比 0.9 不应等于 90 分，极端值要压缩；量能同理，
放量到 3 倍只给 97 分而不是 100，因为「天量」往往同时意味着分歧。

**缺失维度从权重中剔除并重新归一，绝不补 50 分**——补中性会凭空把温度拉回中间。
典型场景：非交易时段涨停池为空（0 家涨停 ≠ 情绪冰点）、东财资金流接口被限流。

**盘中量能必须按交易时段折算**：A 股日内成交额是 U 型的（开盘 30 分钟约占 20%），
直接拿 10 点的成交额除以「20 日全天均额」会永远得出「极度缩量」。页面用 U 型累积曲线做内插。

数据源与取舍：

| 数据块 | 来源 | 说明 |
|---|---|---|
| 全 A 行情 | **新浪 hs_a**（56 页 × 100，并发 4） | 实测 1.5s / 0 失败；东财 push2 在同样批量下会整体限流 |
| 指数点位 | 腾讯 `qt.gtimg.cn` | 1 个批量请求 |
| 涨停/跌停/炸板 | 东财 `push2ex` | 独立域名，抗压；只对当日有效 |
| 主力资金流 | 东财 `push2his` fflow daykline | 必须用 daykline，`fflow/kline` 盘中只返回当天一条；该域偶发整段不可达，此时面板自动切「融资净买入」口径并给出重试按钮 |
| 指数日线 | 腾讯 `web.ifzq.gtimg.cn` | 只有成交量没有成交额，所以量能用「成交量比值」口径 |
| 两融 | 东财数据中心 `RPTA_RZRQ_LSHJ` | 交易所盘后披露，通常滞后 1 个交易日，页面标注日期 |
| 北向 | 东财数据中心 `RPT_MUTUAL_DEAL_HISTORY` | **净买入自 2024-08 起不再披露**（返回 null），只展示成交额活跃度，不参与打分 |
| 行业板块 | 新浪 `newSinaHy`（GBK） | 49 个行业，自带涨跌与领涨股，1 个请求 |
| 股吧人气榜 | 东财 `emappdata`（POST） | 实时人气排名与名次变化，1 个请求 |
| 股吧热帖 | PC `guba.eastmoney.com/list,{code}.html` → 移动端 `mguba.eastmoney.com/mguba/list/{code}` | PC 页带阅读/评论数；高频抓取会触发「身份核实」验证码，此时自动降级移动端（只有标题）。取人气榜最热 4 只 |

| 市场关注度 | 东财数据中心 `RPT_DMSK_TS_STOCKNEW` | 千股千评的市场关注度（0~100）与综合得分，T-1 |

**讨论维度怎么算**

- 讨论分 = 0.6 × 人气榜赚钱效应 + 0.4 × 热帖多空分；
- 人气榜赚钱效应 = 100 × (0.55 × TOP30 上涨占比 + 0.45 × (0.5 + 0.5·tanh(平均涨幅 / 2.5)))，
  逻辑是「散户扎堆的票集体在涨 = 追涨有回报」，集体下跌则是人气变接盘；
- 热帖多空分 = 0.6 × 条数口径 + 0.4 × 热度口径（热度 = 阅读 + 评论×20）；
- 单条标题 = Σ(强词 ±2 / 弱词 ±1)，前置 3 字内的否定词（不/没/别/勿/未/难/无）翻转极性；
- 同一篇资讯会被转发到多个股吧，按标题去重后再统计；
- 「复盘 / 早评 / 公告 / 研报 / 龙虎榜 / 三大指数」这类**资讯型标题记中性**——里面的「涨停/低开」是陈述事实，
  不是观点，不过滤会把多空比系统性拉偏（实测未过滤时看多占比 89%）；
- 多空比旁边会显示有效样本量，少于 20 条时提示「波动较大」。

词典法读不出反讽与谐音，所以这一维只占 12% 权重，不单独构成信号。
**讨论数据只取股吧**：雪球被 WAF 拦、微博需登录态、同花顺论股堂实为投顾平台、财联社接口需 sign 签名、韭研公社不可达。
股吧是唯一稳定可达的高密度散户社区，且自带 PC / 移动端两个入口可互为备份。

热帖取不到时页面不会留白：多空比环图隐藏，人气榜表格占满整行，并明确提示「讨论维度已退化为人气榜单因子」。

**历史情绪曲线是「量价近似温度」**：历史涨跌家数与历史资金流拿不到长序列，
所以那条线只用指数量价派生（0.45 动量 + 0.35 量能 + 0.20 波动），只用于看趋势与拐点，
绝对值不能与当日的六维分直接比较——页面里写明了这一点。

**全市场聚合**：只取 01-05 五类，约 9000 行 / 18 页 / 0.6 秒 / 0.6MB，按报告期缓存 12 小时；
行业归属另拉一次（约 1.7 万行），缓存 7 天。首次进入约 2-3 秒，之后秒开。

**行业层级判定**：东财每只股票挂 一级/二级/三级 三个行业板块，且命名不统一
（煤炭 / 煤炭开采 / 动力煤，银行Ⅱ / 银行 / 股份制银行Ⅲ），无法靠后缀判断。
改用「成分股数量严格分层」的规律：有 Ⅱ 取 Ⅱ，否则取成分数居中者（一级 > 二级 > 三级）。

**聪明资金** = 外资（QFII + 北向通道）+ 国家大基金 + 国家队 + 社保 + 保险，与公募/私募这类交易型资金区分。
跨层对比统一用官方 3 类（QFII+社保+保险），个股层再用穿透口径展开（含大基金/国家队，并单列北向持股）。

**⚠️ 报告期口径（最容易被忽略的坑）**：基金在 **季报（Q1/Q3）只披露前十大重仓股**，
在 **半年报/年报（Q2/Q4）披露全部持仓**。实测沪深300 成分股机构持股均值：半年报 8~11%、季报 6~7%，
所以跨类型比较会得出「一个季度暴增/暴跌」的假象。本页的处理：

- 所有环比、时序、行业趋势都限制在**同口径报告期**之间（Q1/Q3 只和 Q1/Q3 比）；
- 首屏默认展示最近的**全量披露期**（半年报/年报），并提示「最新季报口径偏低，可手动切换」；
- 报告期下拉与头部徽标标注「全量 / 前十大」。

两个口径（官方类型汇总 vs 明细穿透）分开呈现，避免把控股股东误当机构投资者：

| 口径 | 来源 | 用途 |
|---|---|---|
| 官方口径 | `RPT_MAIN_ORGHOLD`（机构持仓报表，多报告期） | 基金/QFII/社保/保险/券商的类型占比演化、环比增减仓 |
| 穿透口径 | `RPT_MAINDATA_MAIN_POSITIONDETAILS`（单期明细）+ 名称规则 | 机构投资者合计、公募/私募/国家大基金/国家队/外资/产业资本结构 |
| 行业归属 | `RPT_BOARD_CONSTITUENT`（`BOARD_TYPE_NEW=2`） | 一级/二级/三级行业，取二级；`in` 批量查询聚合 |

**多源降级（按数据块独立走源链）**

| 数据块 | 源链 | 说明 |
|---|---|---|
| 类型汇总 / 机构明细 | 东财数据中心 | 唯一来源；整块不可用则进入降级模式 |
| 股东户数 | 东财 F10 | 新浪无此字段 |
| 十大流通股东 | 东财 F10 → **新浪 F10** | 新浪为 HTML/GBK 页面，需 `TextDecoder('gbk')` 解码后按表格解析 |

降级模式是**显式**的：页面顶部标「降级：十大流通股东口径」，指标改为占流通股口径，隐藏类型演化/环比/行业视角，并在集中度卡片注明样本仅 10 个主体、HHI 会偏高。

关键处理：

- **官方「其他」不是一类资金**：它把控股股东与产业资本也算了进去（茅台集团 54% 就落在「其他」），因此不并入类型演化图，改用当期明细穿透；
- **东财会把国家大基金标成「私募基金」**，所以分类是「有序正则」：大基金 → 国家队 → 社保 → 保险 → 外资 → 私募品牌 → 公募产品 → 券商 → 产业资本 → 个人，强特征优先；
- **季报披露未完整**：以 `家数_t < 0.8 × 家数_(t−1)` 判定，最新期常只披露一半（如 10 月底的 Q3），此时不计算环比并默认回退到最近完整期，避免把「还没披露」读成「机构撤退」；
- **环比必须同口径**：同时取上一期明细做穿透对比，否则「穿透当期 vs 官方上期」会得出虚假的巨幅变动；
- 机构持仓是**事实数据**，取数失败只给错误与重试，**不生成模拟数据**。

新增代理主机：`datacenter-web.eastmoney.com`（浏览器可直连）、`emweb.securities.eastmoney.com`、`vip.stock.finance.sina.com.cn`（后两者无 CORS 头，走 `/px`）。生产模式需 `npm run serve` 才会启用同样的白名单。

## 设计约定

- **涨红跌绿**（A 股惯例），负仓位按可做空处理
- 所有因子/特征仅用截至当日的数据计算，**无未来函数**（信号序列每 5 日用当时可见数据重算）
- 回测成本模型：双边佣金 + 卖出印花税（顶栏可调，默认万 2.5 + 千 1）
- 机器学习按 70/30 **时序**划分训练/测试，回测仅在样本外区间

## 隐私与数据安全

- **纯前端、零后端**：不收集、不上传任何用户数据。行情、缓存、监控事件流全部保存在浏览器 `localStorage`。
- **仓库不含凭据**：没有 `.env`、API Key、令牌、私钥或账号信息。AI 助手的 Key 由用户在页面自行输入，只存本地，代码里默认值为空。
- **公开接口参数**：代码中出现的第三方 `ut` 之类固定值，是数据源网站前端公开的公共参数（见代码注释），不是密钥、不关联任何账号。
- **代理白名单**：`server.mjs` 的 `/px/{host}/{path}` 只放行白名单域名，不会被当成开放代理使用。

## 数据来源与使用条款

所有数据来自公开行情与资讯接口（腾讯、东方财富、新浪、Naver、Yahoo Finance、SEC EDGAR、StockAnalysis、财联社等）。本项目仅用于个人学习研究，**不对数据做批量抓取、转发售卖或绕过认证**，并对每个 host 设置了最小请求间隔、每分钟预算与失败指数退避（`src/data/rateLimit.ts`）。

这些第三方接口不受本项目控制，可能随时变更或停止服务；使用前请自行确认符合各数据源的服务条款与当地法规。若某数据源要求申请 API Key 或授权，请自行申请后配置，不要提交到仓库。
